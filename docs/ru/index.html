Опыт работы

Пять компаний, один подход к работе: архитектурные решения, которые учитывают реальные ограничения бизнеса и позволяют развивать продукт без остановки разработки.

  1. Отвечал за архитектуру фронтенда и стратегию поэтапной миграции с legacy PHP на Nuxt 4 для крупного банковского продукта. Руководил командой из 4 инженеров, одновременно развивая новую архитектуру и обеспечивая непрерывную поставку функциональности.

    • Руководил техническим развитием команды из 4 инженеров: code review, архитектурная документация, Vitest и Playwright.

Инженерные принципы

Дефолты, которые применяю при архитектурных решениях.

  1. 01

    Предпочитаю поэтапные миграции вместо полного переписывания.

  2. 02

    Архитектура должна снижать сложность системы для команды.

  3. 03

    Бизнес-ограничения — такая же часть архитектуры, как и технические.

  4. 04

    Оптимизирую решения так, чтобы их было легко поддерживать другим инженерам.

  5. 05

    Любая абстракция должна приносить реальную пользу.

  6. 06

    Простые системы масштабируются лучше сложных.

  7. 07

    Тестировать нужно поведение системы, а не детали реализации.

06

Обо мне

Мне нравится проектировать софт, который остаётся поддерживаемым по мере роста продукта.

Десять лет в enterprise-системах — банковский checkout в Сбере, offline PWA для retail, real-time маркетплейсы, мессенджеры. Принимаю архитектурные решения: слоистые границы между UI, бизнес-логикой и data layer; инкрементальные миграции вместо рискованных rewrite; явные tradeoffs, задокументированные для команды.

Работаю с frontend-архитектурой (Vue, Nuxt, SSR, дизайн-системы), backend-сервисами (Django, Go, REST, gRPC) и тесно взаимодействую с продуктовыми и дизайн-командами.

Сейчас наращиваю глубину в AI engineering — LLM, RAG, agents, automation — и веду open-source Nuxt-модуль для анализа аудио в браузере.
